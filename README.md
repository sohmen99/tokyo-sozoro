# Tokyo sozoro（そぞろ）

**行き先を伏せた散歩で、混雑した街から人を歩いて逃がす。**

上野・浅草に立った人に、気分と歩きたい時間だけを聞いて、行き先を伏せたまま抽選する。
案内するのは方角と残りの距離だけ。どこへ向かっていたのかは、着いたときにはじめてわかる。

抽選は、国土交通省の人流オープンデータの実測値で **人出の多い帯から少ない帯へ**重みづけしてある。
つまりこのアプリは、遊んでいるあいだ、勝手に人流を分散させる。

▶ **https://sohmen99.github.io/tokyo-sozoro/**

東京都知事杯オープンデータ・ハッカソン向けの試作です。

## 何ができるか

| 画面 | 中身 |
|---|---|
| 表紙 | 行き先は伏せる、という約束だけを示す。抽選の仕組みは一切明かさない |
| 地図 | 上野・浅草を中心に約 6.4km × 14km。21の基準地点の混雑が時刻とともに変わる |
| 抽選 | 気分（たべもの／寺社・文化／みどり／職人の店）と 30 / 45 / 60 分 |
| 三択 | 正体を伏せたまま3つ。ぼかした写真と、伏せた一行と、距離だけ |
| コンパス | 方角・残り距離・徒歩の推定時間。行き先の名前は出ない。ヒント2回 |
| 到着 | 行き先の正体、写真、説明、歩いた距離、出発地よりどれだけ空いた場所か、出典 |
| 共有 | 到着してから。行き先と歩いた距離と空き具合を1枚の画像に。**出発地は出しません** |
| 印 | 15種のリワードと、歩いた記録 |

- **混雑を避けるかどうかは選べません。** 混んでいる場所は最初から候補に入りません
- **店は営業時間で外れます。** たべもの 8–22時、職人の店 10–19時。寺社とみどりは外から見られるので常時
- **通信は起動時の1回だけ**です。候補地も人流データも地図もファイルの中にあるので、
  失敗しても、間に合わなくても、そのまま動きます

### 生きているデータベース

上の表は全部ファイルに焼き込んであります。そのうえで、起動時に1回だけ
[sozoro-db](https://github.com/sohmen99/sozoro-db) の実体である D1 を裏で読みます。

```
https://sozoro.opd-hackathon-b.workers.dev/api/all?limit=500&layer=…
```

取るのは**写真と説明を持ちうる3レイヤーだけ**（街を見る・体験する・静かに歩く）。
414件・247KB・3リクエストで、実測1.5秒。「食べる」7,136件は営業許可の名簿で
写真も説明も無く3.5MBあるので取りません。そちらは OpenStreetMap 由来の
焼き込み（チェーン除外済み）のほうが行き先として良い。

**落ちても、遅くても、何も起きません。** 焼き込んだ候補地のまま抽選が動きます。
会場の通信が弱くても、Worker が止まっていても、アプリは開く。
DBが直れば、次に開いた人から反映されます。私の再ビルドは要りません。

丁目代表点（`coord_quality='chome'`）とチェーン店は、こちら側でも落としています。
DBの掃除が済めば、この判定が何も落とさなくなるだけです。

## 混雑推定のロジック

**3つの層でできています。実測はいちばん下の層だけです。**

### 層1 — 地域の人出（実測）

国交省の人流オープンデータ、1kmメッシュ、2019年10月。地図の範囲に入る119メッシュの
「休日昼／平日昼の滞在人口」を持ち、任意の地点は周囲2.4km以内のメッシュを**距離の逆二乗で内挿**、
範囲内の5〜95%点で 0〜1 に正規化する。都心はどこも人が多く生値では差が出ないので `pow(x, 1.9)` で
コントラストを立てている。

**限界**: 1kmメッシュでは浅草寺とかっぱ橋が同じセルに入る。施設単位の解像度はない。
この層が担うのは「広域のどこが人出の多い帯か」だけ。データも2019年10月であって、いま現在ではない。

### 層2 — その場所の集客力（推定）

1kmでは解けない施設ごとの差。基準地点は手で置いた値、OSM由来は `wikidata` / `wikipedia` タグの
有無から機械的に 0.22〜0.85、文化財は 0.30、職人の工房は 0.18。

### 層3 — 一日のかたち（推定）

種類ごとの24時間カーブ。寺社は11〜13時が山、飲食は12時と19時の二山、公園は13時、職人の店は14時。

### 合成

```
base = 層3(時間帯) × 層2(集客力) × 週末係数1.15      ※100で頭打ち
混雑 = base + (100 − base) × 層1(人出)^1.9 × 0.50
```

掛け算にすると上位が軒並み100に張り付いて差が消えるので、「その場所そのものの混み方」を土台に、
地域の人出で100側へ引き寄せる形にしている。日曜14時で busy 9 / mid 9 / quiet 3。

### 三択の出し方

引くのは argmax の上位3件ではなく、**重みつきで1枚引いては母集団から抜く**のを3回。
同じ条件でも毎回ちがう3枚が出る。900回試して重複0、距離帯からの逸脱は1件。

写真はぼかす（`blur(11px)` に `scale(1.35)`）。色と明るさは伝わるが、どこかは分からない。
**写真が無ければ、分類ごとの絵を同じだけぼかして敷く。** 線のアイコンだとぼかしても
何も残らず、写真のある枚と並んだときに「はずれ」に見えてしまう。ぼかしたあと残るのは
色と明暗だけなので、絵でも写真でも情報量は同じになる。
伏せた一行が無ければ種別から組んだ文に落ちる。
落とした文は名前から作った数で選ぶので、同じ場所には毎回同じ文が当たる。
ただし同じ回の3枚で文が重なったときだけずらす。手を抜いたように見えるので。

写真のある枚数で組を揃える縛りは、いまは**入れていません**。
データが揃わないと判断したときに足します。

### 抽選での使われ方

```
重み = 距離帯の適合 × 静けさ(100−混雑)^2.2 × 外向き(0.22+0.78×(1−人出)) × 推しエリア × 新規性
```

**推しエリア**は、静けさだけで選ぶと「ただ空いているだけ」の場所が出てしまうので置いた項。
いまは谷中（谷中銀座から900m、×2.4）だけ。谷中が引かれる確率は、上野からの30分で
11.7%→24.1%、浅草からの45分で11.8%→24.3% になる。

距離帯の適合は **選んだ時間の ±7分**。山のかたちで重みを付けたうえで、帯の外は 0 にする。
なだらかな山だけにしておくと、外側の輪ほど候補の数が多いので、1件あたりの重みが小さくても
合計で勝ってしまう。実測で、30分を選んだのに13%が±7分の外へ出ていた（最長44分）。
帯の外を落として 0% になっている。

候補が3枚そろわないときだけ ±11分 → ±17分 と広げ、**広げたことは画面に書く**。
いま広がるのは「職人」の45分と60分だけで、これは候補地の穴（伝統工芸職人37工房が
すべて台東区内にある）がそのまま出ている。

割合（±32%）で持っていたときは、
60分を選んだ人の許容が15分を選んだ人の4倍に広がっていた。分で持てば、どの時間でも
振り幅は同じになる。候補地は**混雑の中心から徒歩67分（直線4.2km）まで**持っていて、
60分＋許容の外側まで途切れない。

**「外向き」の項が層1の実測そのままです。** 人流データ上、人出の多い帯にある候補ほど確率が下がる。
人流誘導が推定ではなく実測値で駆動されている、と言い切れるのはこの一点。

抽選は argmax ではなく重みつきランダム。同じ条件でも毎回ちがう場所が出ます。

## デモモード

外に出ずに、**場所と時刻を自由に置いて**動きを確かめられます。
設定（⚙）から「デモモード」を入れるか、URLに `?demo=1` を付けて開きます。

| 操作 | 効果 |
|---|---|
| 時刻スライダー | 0:00〜23:30 を30分刻み。**混雑推定も営業時間の判定も、まとめてその時刻に従います** |
| 平日 / 休日 | 人流データの休日昼・平日昼を切り替え。混雑の出方が変わります |
| 地図を叩く | その地点に立ちます。立った場所の混雑と、最寄りの基準地点までの距離が出ます |
| 行き先まで歩く | 抽選した行き先へ向かって自動で歩きます。×1 / ×10 / ×60 |

歩く速さは表示に合わせてあります。直線上を進むので、道のりの分（1.3倍）だけ
遅く進める。こうしないと「徒歩45分」と出したのに35分で着いてしまい、数字が嘘になる。

×60 なら 45分の散歩が45秒。針が回り、残り距離が減り、到着画面まで通しで見られます。
デモ中の記録には `demo: true` が付くので、集計から外せます。

## 既知の課題

- **「いま」の混雑は実測できていない。** 都のオープンデータカタログに区部の時間帯別人流はなく、
  国交省のデータは2019〜2021年の月次。リアルタイムには有償の人流データが要る
- **各区の文化財一覧は登録の粒度がばらばら**（江東区992件に対し千代田区80件）で、
  **台東区と文京区は未公開**。混雑の代理には使えなかった（試して捨てた）
- 候補地はビルド時のスナップショット。新しい店は載らない
- 距離は直線距離。隅田川や線路があるので実際の道のりはもっと長い
- 歩きながら画面を見る前提の設計になっている。音声・触覚での案内は未実装

## 開発

単一のHTMLファイルです。ビルド不要。

```bash
python3 -m http.server 8787      # http://localhost:8787
node tools/smoke.js              # 読み込み時の例外とボタンの結線を検査
```

位置情報とコンパスは HTTPS か localhost でしか動きません。

### データを取り直す

```bash
python3 tools/basemap_fetch.py   # 行政界・河川・鉄道・幹線・緑地（OSM）
python3 tools/basemap_gen.py     # 投影して SVG パスに
python3 tools/mesh.py            # 人流メッシュを地図の範囲だけ切り出す
python3 tools/build.py           # 文化財・伝統工芸職人
python3 tools/poi.py             # 飲食・みどり・見どころ（OSM）
```
