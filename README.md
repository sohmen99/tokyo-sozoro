# Tokyo sozoro（そぞろ）

**行き先を伏せた散歩で、混雑した街から人を歩いて逃がす。**

上野・浅草に立った人に、気分と歩きたい時間だけを聞いて、行き先を伏せたまま抽選する。
案内するのは方角と残りの距離だけ。どこへ向かっていたのかは、着いたときにはじめてわかる。

抽選は、国土交通省の人流オープンデータの実測値で **人出の多い帯から少ない帯へ**重みづけしてある。
つまりこのアプリは、遊んでいるあいだ、勝手に人流を分散させる。

▶ **https://sohmen99.github.io/tokyo-sozoro/**

東京都知事杯オープンデータ・ハッカソン向けの試作です。

## 何ができるか

**英語が主です。**日本語は切り替えで出ます。

| 画面 | 中身 |
|---|---|
| 表紙 | 行き先は伏せる、という約束だけ |
| 地図 | 上野・浅草の混雑。ここから歩き方を選ぶ |
| 歩き方 | **あてもなく歩く**（15分ずつ、一か所ずつ）か、**向こうまで抜ける**（駅までの一本道） |
| 三択 | 正体を伏せたまま3つ。ぼかした写真と、伏せた一行と、距離だけ |
| コンパス | 方角と残り距離だけ。行き先の名前は出ない |
| 到着 | 正体、写真、説明、近くにあるもの、出典 |
| つづき | **もう一か所いくか、ここで終えるか。**上野まで戻る徒歩分を添える |
| 印 | 15種のリワードと、歩いた記録 |

- **1区間は徒歩15分（前後7分）に固定。**時間はもう選ばせません
- **あてもなく歩けない場所では、その選択肢が押せません。**上野から15分の範囲に候補が3つ無いときです。その場合は駅まで抜けるほうへ寄せます
- **向こうまで抜けるモードは、選んだ時点で道筋が決まります。**途中で「まだ続けるか」は聞きません。着いたら電車で帰れます

## 混雑推定のロジック

**3つの層でできています。実測はいちばん下の層だけです。**

### 層1 — 地域の人出（実測）

国交省の人流オープンデータ、1kmメッシュ、2019年10月。地図の範囲に入る119メッシュの
「休日昼／平日昼の滞在人口」を持ち、任意の地点は周囲2.4km以内のメッシュを**距離の逆二乗で内挿**、
範囲内の5〜95%点で 0〜1 に正規化する。都心はどこも人が多く生値では差が出ないので `pow(x, 1.9)` で
コントラストを立てている。

**限界**: 1kmメッシュでは浅草寺とかっぱ橋が同じセルに入る。施設単位の解像度はない。
この層が担うのは「広域のどこが人出の多い帯か」だけ。データも2019年10月であって、いま現在ではない。

### 層2 — その場所の集客力（推定）

1kmでは解けない施設ごとの差。基準地点は手で置いた値、OSM由来は `wikidata` / `wikipedia` タグの
有無から機械的に 0.22〜0.85。行き先は種類ごとで、飲食 0.24 / 文化財 0.32 / みどり 0.25。

### 層3 — 一日のかたち（推定）

種類ごとの24時間カーブ。寺社は11〜13時が山、飲食は12時と19時の二山、公園は13時。
飲食だけは8〜22時の外を閉店として抽選から外す。寺社と公園は門の外からでも成立するので時間を持たない。

### 合成

```
base = 層3(時間帯) × 層2(集客力) × 週末係数1.15      ※100で頭打ち
混雑 = base + (100 − base) × 層1(人出)^1.9 × 0.50
```

掛け算にすると上位が軒並み100に張り付いて差が消えるので、「その場所そのものの混み方」を土台に、
地域の人出で100側へ引き寄せる形にしている。日曜14時で busy 9 / mid 9 / quiet 3。

色は **40未満が緑（空き）／40〜69が赤（やや混雑）／70以上が紫（混雑）**。
混むほど赤から紫へ抜ける。地図のヒートは半径 `22 + 混雑 × 0.36` px、濃さ `0.10 + 混雑/100 × 0.34`、
そこへ `stdDeviation=26` のぼかしと全体 opacity 0.85 がかかる。ぼかしが効くので
小さい丸ほど中心まで薄まり、空いている場所は自然に目立たなくなる。

### 三択の出し方

引くのは argmax の上位3件ではなく、**重みつきで1枚引いては母集団から抜く**のを3回。
同じ条件でも毎回ちがう3枚が出る。900回引いて重複0、距離帯からの逸脱は1件。

写真はぼかす（`blur(11px)` に `scale(1.35)`）。色と明るさは伝わるが、どこかは分からない。
**写真が無ければ、分類ごとの絵を同じだけぼかして敷く。** 線のアイコンだとぼかしても
何も残らず、写真のある枚と並んだときに「はずれ」に見えてしまう。ぼかしたあと残るのは
色と明暗だけなので、絵でも写真でも情報量は同じになる。
伏せた一行が無ければ種別から組んだ文に落ちる。
落とした文は名前から作った数で選ぶので、同じ場所には毎回同じ文が当たる。
ただし同じ回の3枚で文が重なったときだけずらす。手を抜いたように見えるので。

### 写真

**58件に実写真が入っています。**採ってあるのは、その場所そのものを写したものだけ。
出所は Wikimedia Commons で、撮影者とライセンスは Commons API から引いた値を
到着画面に添えます。書き出しは
[sozoro-ios](https://github.com/sohmen99/sozoro-ios) の `tools/photos.py`。

**写真のある枚数で組は揃えていません。**三択ではぼかす（`blur(11px)`）ので、
写真の枚と絵の枚は並べても見分けがつきません。

### 抽選での使われ方

```
重み = 距離帯の適合 × 静けさ(100−混雑)^2.2 × 外向き(0.22+0.78×(1−人出)) × 推しエリア × 新規性
```

**推しエリア**は、静けさだけで選ぶと「ただ空いているだけ」の場所が出てしまうので置いた項。
谷中（谷中銀座から900m、×2.4）に置いてあります。

距離帯の適合は **徒歩15分の ±7分**。山のかたちで重みを付けたうえで、帯の外は 0 にする。
なだらかな山だけにしておくと、外側の輪ほど候補の数が多いので、1件あたりの重みが小さくても
合計で勝ってしまう。帯の外を落として 0% になっている。

候補が3枚そろわないときだけ ±11分 → ±17分 と広げ、**広げたことは画面に書く**。

**「外向き」の項が層1の実測そのままです。** 人流データ上、人出の多い帯にある候補ほど確率が下がる。
人流誘導が推定ではなく実測値で駆動されている、と言い切れるのはこの一点。

抽選は argmax ではなく重みつきランダム。同じ条件でも毎回ちがう場所が出ます。

## デモモード

外に出ずに、**場所と時刻を自由に置いて**動きを確かめられます。
設定（⚙）から「デモモード」を入れるか、URLに `?demo=1` を付けて開きます。

| 操作 | 効果 |
|---|---|
| 時刻スライダー | 0:00〜23:30 を30分刻み。**混雑推定も営業時間の判定も、まとめてその時刻に従います** |
| 平日 / 休日 | 人流データの休日昼・平日昼を切り替え。混雑の出方が変わります |
| 地図を叩く | その地点に立ちます。立った場所の混雑と、最寄りの基準地点までの距離が出ます |
| 行き先まで歩く | 抽選した行き先へ向かって自動で歩きます。×1 / ×10 / ×60 |

歩く速さは表示に合わせてあります。直線上を進むので、道のりの分（1.3倍）だけ
遅く進める。こうしないと「徒歩15分」と出したのに11分で着いてしまい、数字が嘘になる。

×60 なら 15分の散歩が15秒。針が回り、残り距離が減り、到着画面まで通しで見られます。
デモ中の記録には `demo: true` が付くので、集計から外せます。

## 開発

単一のHTMLファイルです。ビルド不要。

```bash
python3 -m http.server 8787      # http://localhost:8787
node tools/smoke.js              # 読み込み時の例外とボタンの結線を検査
```

位置情報とコンパスは HTTPS か localhost でしか動きません。

### データを取り直す

```bash
python3 tools/basemap_fetch.py   # 行政界・河川・鉄道・幹線・緑地（OSM）
python3 tools/basemap_gen.py     # 投影して SVG パスに
python3 tools/mesh.py            # 人流メッシュを地図の範囲だけ切り出す
python3 tools/build.py           # 文化財
python3 tools/poi.py             # 飲食・みどり・見どころ（OSM）
```
